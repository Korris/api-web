TapShow Create Flow

Toàn bộ lời gọi API để tác giả tạo một TapShow post hoàn chỉnh: post → nhân vật → chapter → segment → rẽ nhánh → publish. Mỗi bước ghi rõ body gửi lên và dữ liệu cần giữ lại cho bước sau.

Base /api/tapshow/ Auth Authorization: Bearer <jwt> cho mọi lời gọi ghi Body JSON, trừ upload là multipart/form-data field File Chi tiết: docs/tapshow-area.md

Tổng quan

Các bước

1

Upload thumbnail

Mọi file đều upload trước, API trả hashId; bước sau tham chiếu bằng hashId đó. File chưa gắn vào đâu là bản tạm, chỉ chủ upload mới dùng được.

POSTfile/upload-mediaauth · multipart
Gửi
File: <ảnh jpg/png/webp…>
Nhận
{ "hashId": "a1b2…", "url": "https://media…/x.jpg",
  "width": 1200, "height": 1600, "size": 348120 }

Ảnh được nén lại thành JPEG. Giới hạn đọc từ GET /api/identity/config → thumbnailCoverSize (bytes).

2

Tạo post

Trả về hashId của post, dùng cho mọi bước sau. Post tạo xong là Public ngay nhưng chưa có chapter nào để đọc.

POSTtapshowauth
Gửi
{
  "title": "Bánh mì: Một miếng, hai lựa chọn",
  "summary": "Bữa sáng quyết định cả ngày…",
  "thumbnailHashId": "a1b2…",
  "isCurrentUserAuthor": true,
  "authorName": "",
  "isMature": false,
  "isCompleted": false,
  "permission": 0
}
Nhận (rút gọn)
{ "id": "guid", "hashId": "p7Qx…",
  "title": "…", "thumbnailUrl": "…",
  "permission": 0, "status": 1,
  "chapterCount": 0, "commentCount": 0 }

permission 0 Public · 1 Private (chỉ owner) · 2 Premium (chapter khoá với người không premium). isCurrentUserAuthor false thì authorName bắt buộc.

3

Tạo nhân vật (một lần cho cả post)

Nhân vật thuộc post, không thuộc segment. Segment chỉ trỏ tới nhân vật bằng characterId; đổi tên hay avatar ở đây là đổi cho mọi segment.

POSTfile/upload-mediaauth · multipart

Avatar, tuỳ chọn. Cùng endpoint với thumbnail.

POSTcharacterauth
Gửi
{
  "postHashId": "p7Qx…",
  "name": "VIPHIEN",
  "avatarHashId": "c3d4…",
  "order": null
}
Nhận
{ "id": "ch-guid", "postId": "…",
  "name": "VIPHIEN", "avatarUrl": "…",
  "avatarHashId": "c3d4…", "order": 1 }

Lặp cho từng nhân vật. Giữ lại id để gắn vào segment. Danh sách: GET character/post/{postHashId}. Sửa/xoá: PUT|DELETE character/{id}; xoá thì segment đang dùng giữ nội dung, characterId về null.

4

Tạo chapter (Draft)

Tạo ở trạng thái Draft để soạn segment; người đọc không thấy chapter Draft. Publish ở bước 7.

POSTchapterauth
Gửi
{
  "postHashId": "p7Qx…",
  "title": "Một miếng, hai lựa chọn",
  "order": null,
  "status": 0
}
Nhận
{ "id": "…", "hashId": "kL9m…",
  "title": "…", "order": 1, "status": 0,
  "segmentCount": 0, "endingCount": 0 }

status 0 Draft · 1 Public. order null = nối cuối danh sách. Giữ lại hashId của chapter cho bước 5.

5

Tạo segment, theo đúng thứ tự đọc

Mỗi segment là một màn: ảnh + nhân vật nói + lời thoại + audio. Tạo lần lượt, không cần nối chúng lại: segment không có choice tự đi tới segment kế theo order (nút Next). Segment có order nhỏ nhất là màn mở đầu.

POSTfile/upload-mediaauth · multipart

Ảnh của màn, tuỳ chọn.

POSTfile/upload-audioauth · multipart

Audio lời thoại, tuỳ chọn. Nhận mp3, m4a, aac, wav, ogg. Giới hạn: tapShowAudioSize trong config (mặc định 10 MB). Nhận về { hashId, url, size }.

POSTsegmentauth
Gửi
{
  "chapterHashId": "kL9m…",
  "characterId": "ch-guid",
  "title": "Cảnh 14",
  "imageHashId": "e5f6…",
  "narration": "Giữ giấy gọn, cắn miếng vừa, nhai xong rồi nói. Còn ớt thì tùy BossDat.",
  "audioHashId": "g7h8…",
  "order": null,
  "isEnding": false
}
Nhận
{ "id": "seg-guid", "chapterId": "…",
  "imageUrl": "…", "imageHashId": "e5f6…",
  "narration": "…", "audioUrl": "…", "audioHashId": "g7h8…",
  "characterId": "ch-guid", "characterName": "VIPHIEN",
  "characterAvatarUrl": "…",
  "order": 14, "isEnding": false,
  "kind": "Next", "nextSegmentId": null,
  "choices": [] }

Cần ít nhất imageHashId hoặc narration. characterId phải là nhân vật của cùng post, null = người dẫn truyện. Màn kết thúc: isEnding: true. Giữ lại id của từng segment cho bước 6.

Sửa: PUT segment/{id} cùng body (bỏ chapterHashId). Với imageHashId / audioHashId: gửi lại hash cũ = giữ, hash mới = thay, null = bỏ. Xoá: DELETE segment/{id}, các choice trỏ tới nó bị xoá theo.

6

Đặt lựa chọn ở màn rẽ nhánh

Chỉ gọi cho segment mà người đọc phải chọn. Cần các segment đích tồn tại trước (tạo ở bước 5). Lời gọi thay toàn bộ choice của segment.

PUTsegment/{id}/choicesauth
Gửi
{
  "choices": [
    { "label": "Cắn miếng to",  "targetSegmentId": "seg-B" },
    { "label": "Cắn miếng nhỏ", "targetSegmentId": "seg-C" }
  ]
}
Nhận
{ "id": "seg-A", …,
  "kind": "Choice", "isEnding": false,
  "choices": [
    { "id": "…", "label": "Cắn miếng to",
      "order": 0, "targetSegmentId": "seg-B" },
    { "id": "…", "label": "Cắn miếng nhỏ",
      "order": 1, "targetSegmentId": "seg-C" } ] }

Tối đa 8. Đích phải cùng chapter, không trùng nhau, không tự trỏ. Có choice → segment thành Choice và isEnding tự về false. Gửi "choices": [] → về Next thường.

7

Publish chapter

Đổi trạng thái sang Public; từ lúc này chapter xuất hiện trong GET chapter/post/{postHashId} và chapterCount của post tăng.

PUTchapter/{hashId}auth
Gửi
{ "title": "Một miếng, hai lựa chọn", "order": 1, "status": 1 }
Nhận
{ "hashId": "kL9m…", "status": 1, "publishDate": "2026-09-22T08:00:00Z",
  "segmentCount": 17, "endingCount": 2 }

Khi truyện hoàn tất: PUT tapshow/{hashId} với isCompleted: true (body như bước 2, gửi lại thumbnailHashId cũ để giữ ảnh).

Segment: Next, Choice hay Ending

API tự tính kind cho từng segment khi trả chapter. Client không tự suy luận, chỉ đọc trường này.

kind: "Next"

Không có choice, không phải kết. Nút Next đi tới nextSegmentId (segment kế theo order). null = hết chapter.

kind: "Choice"

Có ít nhất 1 choice. Hiện choices[] làm nút, bấm → targetSegmentId. Có choice thì không thể là ending.

kind: "Ending"

Tác giả đánh isEnding: true. Truyện dừng ở đây. Một chapter có thể có nhiều ending (endingCount).

Ví dụ: chapter 5 màn, 2 kết thúc

Next theo orderChoiceEnding

S3 có order 3 và không có choice nên Next của nó là S4 (order 4). S5 đứng sau S4 theo order nhưng chỉ tới được qua choice của S2. Thứ tự order quyết định Next; choice quyết định nhánh.

#Lời gọiBody chínhGiữ lại

2POST tapshowtitle, summary, thumbnailHashIdpostHash
3POST character ×2postHashId, name "VIPHIEN" / "BossDat", avatarHashIdcharA, charB

Kiểm tra lại từ phía người đọc

Sau bước 7, gọi GET chapter/{chapHash} (không cần auth) để xem đúng thứ đọc giả nhận: startSegmentId = S1, mỗi segment có kind, nextSegmentId, choices, characterName, characterAvatarUrl, imageUrl, audioUrl. Toàn bộ đồ thị nằm trong một response; người đọc điều hướng cục bộ, không gọi thêm.

Lỗi hay gặp
  • 400 "must reference your own uploads": hashId đã dùng rồi, sai loại (ảnh vs audio), hoặc của user khác. Upload lại.
  • 400 "CharacterId must be a character of the same post": nhân vật thuộc post khác hoặc đã xoá.
  • 400 "An ending segment cannot have choices": xoá choice (gửi []) trước khi đặt isEnding: true.
  • 400 "Each choice must target a different existing segment…": target trùng, tự trỏ, hoặc ở chapter khác.
  • 403 E309: không phải chủ post. 404 E204: post/chapter/segment không tồn tại hoặc không được thấy.
